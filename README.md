Решение кейса финала **«Космос: Без права на брак»** — автоматический контроль качества деталей в космической отрасли.

## Постановка

> Разработайте интеллектуальное решение для автоматического контроля качества деталей в космической отрасли с учётом условий закрытого производства и ограниченности доступных данных. Итог представьте в виде архитектуры и/или MVP системы, способной выявлять дефекты, анализировать производственные процессы и интегрироваться в существующую ИТ-инфраструктуру предприятия.

Из постановки следуют три ограничения, которые определяют решение сильнее выбора модели:

- **Закрытое производство.** Данные не покидают контур предприятия, поэтому решение должно работать без внешних сервисов и без доступа в интернет.
- **Мало данных.** Размеченных примеров дефектов немного, а у редких видов брака их может не быть вовсе.
- **Интеграция.** Результат — не отдельная модель, а часть действующей ИТ-инфраструктуры предприятия.

Материалы кейса выдаются на старте финала; разбор данных и выбранный подход появятся здесь, как только будут измерены.

## Быстрый старт

```bash
uv sync --extra dev
```

Проверить, что всё сходится:

```bash
uv run pytest
uv run ruff check src tests
```

То же самое делает CI на каждом пуше.

## Устройство репозитория

```
src/zero_defect/
  config.py     пути, от которых считаются остальные модули
tests/          проверки пакета
```

Структура растёт по этапам конвейера, а не по типам файлов: каждый этап — отдельный подпакет, скрипты в `scripts/` остаются тонкими точками входа.

## Данные

Выданные данные в репозиторий не попадают: производство закрытое, и публиковать материалы предприятия мы не вправе. Их место — каталог `data/`, он исключён из git. Обученные веса тоже не хранятся в репозитории — они воспроизводятся из кода и данных.
