Решение кейса **«Космос: Без права на брак» — интеллектуальный контроль качества деталей в космической отрасли.** Система собирает результаты контроля, производственные события, действия операторов и состояние оборудования в единую историю изделия и помогает людям обоснованно разбирать несоответствия: где дефект возник, на каком основании это видно, что ещё могло к нему привести и каких сведений не хватает.

Кейс звучит как задача распознавания, но постановка её исключает: вход — уже готовые результаты внешнего анализатора, а собственные CV-модели не требуются. Поэтому ядро решения — прослеживаемость и доказательный разбор, а проект комплекса «камеры + ИИ» описан отдельно и подключается через тот же контракт событий. Разбор постановки и критериев — в [docs/research.md](docs/research.md).

## Быстрый старт

```bash
uv sync --extra dev
uv run uvicorn zero_defect.integration.emulator:app --port 8100 &
uv run uvicorn zero_defect.serving.api:create_app --factory --port 8000
```

Интерфейс — на `http://localhost:8000`, спецификация API — на `/docs`. При первом запуске сервис создаёт ключи в `var/keys` и проигрывает демонстрационный набор — семь проверочных ситуаций на одной линии. Пользователь выбирается в правом верхнем углу: права контролёра, мастера, технолога, руководителя и администратора различаются.

В контейнерах, вместе с эмулятором внешней системы:

```bash
docker compose up --build
```

Проверить, что всё сходится:

```bash
uv run pytest
uv run ruff check src tests scripts
uv run python scripts/check_scenarios.py
uv run python scripts/check_generated.py
uv run python scripts/check_compat.py
uv run python scripts/export_openapi.py --check
```

То же делает CI на каждом пуше: правка, которая ломает обязательную ситуацию постановки, разводит сгенерированный код со схемой или делает несовместимое изменение контракта, падает там, а не на защите.

## Что делает система

**Приём событий.** Контракт — JSON Schema двух версий (1.0 и 1.1), из которой порождаются модели, документация и перечисления интерфейса. Сообщение проверяется целиком, и источник получает полный список проблем с путём до поля. Повторная доставка не учитывается дважды, тот же идентификатор с другим содержимым уходит в карантин, опоздания и расхождения часов помечаются, пропуски в нумерации источника видны на экране линии.

**История изделия.** Изделие, его компоненты, каждое выполнение операции с оператором и оборудованием, паузы, повторные обработки, проверки, состояния станков и действия операторов — в одной хронологии. История строится по времени возникновения, поэтому не зависит от порядка поступления.

**Несоответствия.** Сообщение анализатора, подтверждённое несоответствие, предполагаемая причина и подтверждённая причина — четыре разных статуса. Решение контролёра — отдельная запись с автором и обоснованием; исходное сообщение не меняется никогда. Повторные наблюдения одного дефекта связываются в одну карточку и не увеличивают показатели.

**Разбор обстоятельств.** Этап возникновения определяется по последнему достоверному контролю, который дефекта не видел. Проверка с плохим снимком или низкой уверенностью этап не ограничивает и попадает в недостающие сведения, а «признаков нет» при плохом наблюдении не превращается в «годно». Отклонение станка в окне операции даёт гипотезу о проблеме оборудования. Оператор — участник операции, а не виновник: ошибка оператора бывает только подтверждённой человеком.

**Аналитика.** Проверенные изделия и изделия с несоответствиями, дефекты по типам, линиям и участкам, установленные и неустановленные причины, длительности по изделию, участку, оператору и смене с пометкой происхождения, повторные обработки, подтверждённые ошибки по сопоставимым работам, прохождение с первого раза, задержка обнаружения. Входной брак, проблемы оборудования, ошибки операторов и гипотезы учитываются раздельно. История выгружается в OCEL 2.0 для анализа процессов.

**Защита.** Журнал только дописывается, содержимое записей зашифровано AES-256-GCM, записи связаны цепочкой хешей, пакет подписан гибридно Ed25519 + ML-DSA-65, подписанная голова журнала хранится отдельно от базы. Ключи вне кода и репозитория, профили сменные, старые записи не перешифровываются. Права ролей и аудит критических действий — в одной шине безопасности.

**Интеграции.** Двусторонний обмен с эмулятором MES: задания приходят и становятся событиями, итоги уходят через исходящую очередь с повторами и списком недоставленных. Адаптеры 1С (OData), Галактики ERP (XML-обмен), MES по ISA-95 и импорт состава сборки из КОМПАС-3D. Новый адаптер подключается строкой конфигурации.

## Что проверено

- **8 из 8** обязательных ситуаций постановки сходятся с ожиданиями, записанными отдельно от входа до первого прогона ([docs/scenarios.md](docs/scenarios.md), `reports/metrics/scenarios.json`).
- **Нагрузочный прогон**: 2187 сообщений, из них 2100 уникальных. Один и четыре обработчика, перемешанный порядок и сбой центра с повторной доставкой дают одинаковый итог до хеша; каждое уникальное событие принято ровно один раз, все повторы распознаны (`reports/metrics/load.json`).
- **Вмешательство в журнал** — изменение записи в обход приложения, удаление, пересчёт цепочки, отрезание хвоста — обнаруживается; обычное изменение запрещено.

```
  events/       JSON Schema контракта событий, версии 1.0 и 1.1 — единый источник истины

src/zero_defect/
  contracts/    кодогенерация, сгенерированные модели, проверка совместимости версий

  history/      история изделия
  quality/      несоответствия и решения
  analysis/     разбор обстоятельств, аналитика, выгрузка OCEL
  integration/  порт, адаптеры, исходящая очередь, эмулятор внешней системы
  security/     роли, токены, подпись источников, шина безопасности

tests/          ядро, журнал, приём, решения, сценарии, масштабирование, интеграции, API
data/
  scenarios/    восемь проверочных ситуаций: вход и ожидаемый итог отдельно
  demo/         демонстрационный набор
reports/metrics/ итоги сценариев и нагрузочного прогона
docs/           исследование, архитектура, защита, интеграции, проект «камеры + ИИ»,
                сценарии, API, контракт, результаты, экономика
```
