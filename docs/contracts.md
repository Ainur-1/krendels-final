# Контракт событий zd-events

Документ сгенерирован из JSON Schema командой `uv run python scripts/generate_contracts.py` и руками не правится. Генератор: datamodel-code-generator 0.83.0.

Принимаемые версии: `1.0`, `1.1`. Ниже — описание последней версии, `1.1`; схемы всех версий лежат в `contracts/events/`.

Версия контракта (`schema_version`) не связана с версией анализирующего модуля (`analyzer_version`) и с версией приложения. Время поступления фиксирует принимающая система, источник его не передаёт.

## Поведение при отклонениях от контракта

| ситуация | поведение | код |
|---|---|---|
| неизвестная версия сообщения | сообщение отклоняется в карантин целиком | `unknown_schema_version` |
| неизвестный тип события | отклоняется в карантин | `unknown_event_type` |
| отсутствует обязательное поле | отклоняется, в ответе путь до поля | `missing_field` |
| неизвестное значение перечисления | отклоняется: смысл значения неизвестен, и угадывать его нельзя | `unknown_enum_value` |
| добавлено необязательное поле | принимается, поле сохраняется в исходном сообщении и в разборе не участвует | `unknown_optional_field` (предупреждение) |
| несовместимое изменение схемы | ловится до выпуска: `scripts/check_compat.py` сравнивает версии в CI | `breaking` |

Отклонённое сообщение не теряется: оно записывается в журнал вместе со списком ошибок и видно на странице карантина.

## Генерация и проверки

Генератор: datamodel-code-generator 0.83.0, версия закреплена в `pyproject.toml`. Команда: `uv run python scripts/generate_contracts.py`. Из схем порождаются:

| файл | что это |
|---|---|
| `src/zero_defect/contracts/generated/v1_0.py` | модели pydantic версии 1.0 |
| `src/zero_defect/contracts/generated/v1_1.py` | модели pydantic версии 1.1 |
| `src/zero_defect/contracts/generated/__init__.py` | реестр моделей по версии и типу события |
| `docs/contracts.md` | этот документ |
| `src/zero_defect/serving/static/contract.js` | перечисления контракта для интерфейса |

Автоматические проверки в CI:

- `scripts/check_generated.py` — пересобирает всё перечисленное во временный каталог и падает, если файлы в репозитории разошлись со схемой или поправлены руками;
- `scripts/check_compat.py` — сравнивает соседние версии и падает на несовместимом изменении;
- `scripts/export_openapi.py --check` — сверяет спецификацию API с кодом сервиса.

Воспроизводимое несовместимое изменение, которое проверка ловит до передачи результата: `uv run python scripts/check_compat.py contracts/events/v1.1.schema.json contracts/examples/breaking_change_v1.2.schema.json` — удалено поле, поле стало обязательным, из перечисления убрано значение; команда завершается с ошибкой.
