# Публичный стенд Render

После финала это основной публичный адрес сервиса: [https://krendels-final.onrender.com/](https://krendels-final.onrender.com/). Стенд на VPS, где проходила защита, закрыт; его настройка сохранена в [deploy-vps.md](deploy-vps.md). Конфигурация Render находится в [`render.yaml`](../render.yaml); описание полного запуска трёх контейнеров — в [`README.md`](../README.md) и [`architecture.md`](architecture.md).

## Что развёртывается

- Один бесплатный Docker web service из ветки `main` с проверкой `/api/health`.
- Демонстрационный режим с условными данными. База SQLite находится в `/app/var/render-preview.sqlite3`, ключи — в `/app/var/keys`. Оба каталога находятся в одном временном файловом пространстве сервиса.
- Адаптер внешнего MES-эмулятора отключён значением `ZD_INTEGRATION_ENABLED=none`, потому что он не запущен отдельным процессом на этом стенде. Двусторонний обмен и PostgreSQL показываются на финальном VPS.

## Действующий сервис

26 сентября 2026 года в проекте Render `krendels-final` настроен существующий бесплатный Docker web service `krendels-final` в регионе Oregon. Он подключён к `Ainur-1/krendels-final`, ветке `main`; адрес — [https://krendels-final.onrender.com/](https://krendels-final.onrender.com/). Настройки сервиса: `PORT=8000`, `ZD_STORAGE_URL=sqlite:////app/var/render-preview.sqlite3`, `ZD_SECURITY_DEMO=true`, `ZD_INTEGRATION_ENABLED=none`, Health Check Path `/api/health`, Auto-Deploy `After CI Checks Pass`.

Коммит `51d11d3` получил статус **Live**. Независимый HTTPS-запрос вернул `200` для главной страницы и `/api/health`; последняя ответила `{"status":"ok","version":"0.1.0","records":4737}`. Демонстрационный вход `controller` / `controller` и запрос `/api/me` с выданным токеном тоже прошли. Полный сценарий через интерфейс ещё не проверен.

Автодеплой проверен на следующем коммите: [GitHub Actions run #8](https://github.com/Ainur-1/krendels-final/actions/runs/36233523028) завершился успешно для `daca525`, после чего Render автоматически развернул тот же коммит со статусом **Live**; внешний запрос `/api/health` вернул `200`. Это подтверждает связку GitHub CI → Render для временного стенда. При последующих изменениях сверяйте новый коммит и результат отдельно.

Сервис был создан вручную до появления `render.yaml`, поэтому Render не синхронизирует его настройки с этим файлом автоматически. `render.yaml` описывает воспроизводимую конфигурацию для нового Blueprint; при изменении файла нужно отдельно сверять настройки действующего сервиса. Не создавайте второй Blueprint-сервис для текущего стенда без необходимости.

Для проверки после очередного изменения: сверить SHA последнего развёртывания с `main`, открыть адрес и `/api/health`, затем пройти демонстрационный сценарий в интерфейсе.

## Ограничения и безопасность

Бесплатный сервис засыпает после 15 минут без входящих запросов; первый запрос после сна может ждать около минуты. Рост данных ограничен трижды: база создаётся заново при каждом пробуждении, живая эмуляция запускает новые изделия только пока экран линии кто-то смотрит, и за один запуск она выдаёт не больше 35 тыс. событий — с демонстрационной историей это около 300 МБ памяти при лимите бесплатного тарифа 512 МБ. Его локальные файлы теряются при засыпании, перезапуске и новом развёртывании. Поэтому действия пользователей и журнал на этом стенде **не сохраняются между запусками**. Система заново создаёт условную демонстрационную историю. Реальные производственные данные и секреты здесь не размещаются.

Режим `ZD_SECURITY_DEMO=true` показывает выбор роли, который подставляет демонстрационные логин и пароль в форму входа; пароль этих условных пользователей совпадает с логином. Этот публичный стенд нельзя представлять как производственное развёртывание с защищённым доступом. На Render открыт только HTTP-порт приложения; отдельный порт MES-эмулятора не публикуется. Render предоставляет HTTPS для адреса `onrender.com`, но внутренние механизмы защиты и ограничения решения описаны отдельно в [`security.md`](security.md).

Настройки для VPS должны быть проверены независимо: там используются PostgreSQL, отдельный том ключей, MES-эмулятор и публичная ссылка по IP-адресу. Проверка временного стенда Render не заменяет проверку VPS перед переносом в GitVerse.
