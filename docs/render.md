# Временный стенд Render

Этот стенд нужен для просмотра интерфейса командой до продления VPS. Итоговая ссылка для жюри будет вести на VPS. Конфигурация Render находится в [`render.yaml`](../render.yaml); описание полного запуска трёх контейнеров — в [`README.md`](../README.md) и [`architecture.md`](architecture.md).

## Что развёртывается

- Один бесплатный Docker web service из ветки `main` с проверкой `/api/health`.
- Демонстрационный режим с условными данными. База SQLite находится в `/app/var/render-preview.sqlite3`, ключи — в `/app/var/keys`. Оба каталога находятся в одном временном файловом пространстве сервиса.
- Адаптер внешнего MES-эмулятора отключён значением `ZD_INTEGRATION_ENABLED=none`, потому что он не запущен отдельным процессом на этом стенде. Двусторонний обмен и PostgreSQL показываются на финальном VPS.

## Создание сервиса

1. Подключить к Render GitHub-репозиторий `Ainur-1/krendels-final` и выбрать ветку `main`.
2. Создать Blueprint из `render.yaml`. Убедиться, что план указан как **Free**; платный план для этого временного стенда не нужен.
3. После успешной сборки открыть выданную Render ссылку `https://…onrender.com/` и `/api/health`. Затем открыть интерфейс, выбрать роль и пройти один демонстрационный сценарий.
4. Сверить коммит развёртывания с коммитом ветки `main` и проверить, что автодеплой происходит после успешных проверок CI. До такого прогона считать автодеплой настроенным, но не подтверждённым.

## Ограничения и безопасность

Бесплатный сервис засыпает после 15 минут без входящих запросов; первый запрос после сна может ждать около минуты. Его локальные файлы теряются при засыпании, перезапуске и новом развёртывании. Поэтому действия пользователей и журнал на этом стенде **не сохраняются между запусками**. Система заново создаёт условную демонстрационную историю. Реальные производственные данные и секреты здесь не размещаются.

Режим `ZD_SECURITY_DEMO=true` позволяет выбирать роль без пароля. Этот публичный стенд нельзя представлять как производственное развёртывание с защищённым доступом. На Render открыт только HTTP-порт приложения; отдельный порт MES-эмулятора не публикуется. Render предоставляет HTTPS для адреса `onrender.com`, но внутренние механизмы защиты и ограничения решения описаны отдельно в [`security.md`](security.md).

Настройки для VPS должны быть проверены независимо: там используются PostgreSQL, отдельный том ключей, MES-эмулятор и публичная ссылка по IP-адресу. Проверка временного стенда Render не заменяет проверку VPS перед переносом в GitVerse.
